# Bug report

- **ID:** BUG-001
- **Title:** DELETE /booking/{id} answers 201 Created instead of 204 No Content
- **Endpoint:** DELETE /booking/{id}
- **Severity / Priority:** High / P1 - same class of change as last month's 'cancellation failed' incident: a client that treats anything other than 204 as failure shows an error although the booking was deleted.
- **Environment:** Public server `https://restful-booker.herokuapp.com` (REST Assured run, 2026-11-17: 46 tests, 19 failures = the `known-defect` tests) and a local run of the upstream Restful-Booker source (commit 619d031) at `http://localhost:3001` (Postman/Newman, 2026-11-15). Response examples below are from the local run.

## Steps to reproduce
1. Create a booking: `POST /booking` with a valid body and note `bookingid`.
2. Get a token: `POST /auth` with the admin credentials.
3. Send `DELETE /booking/{bookingid}` with header `Cookie: token=<token>`.
4. Send `GET /booking/{bookingid}` - it correctly returns 404, so the delete itself worked.

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
TOKEN=$(curl -s -X POST $BASE/auth -H "Content-Type: application/json" -d '{"username":"admin","password":"password123"}' | sed 's/.*"token":"\([^"]*\)".*/\1/')
curl -i -X DELETE $BASE/booking/<bookingid> -H "Cookie: token=$TOKEN"
```

## Expected result (quote the contract)
Contract, Endpoints table: `DELETE /booking/{id}` -> expected success **204 No Content**.

## Actual result (status, body, timing)
Status **201 Created**, `Content-Type: text/plain; charset=utf-8`, body `Created` (1-3 ms). The booking is deleted (the follow-up GET returns 404), only the status code/body deviate.

```
HTTP/1.1 201 Created
Content-Type: text/plain; charset=utf-8

Created
```

## Evidence
Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 03, request '5. DELETE /booking/{id}' (assertion 'Status code is 204 (No Content)'); REST Assured: `BookingLifecycleBddTest.deleteBooking`, `fullFlow` (tag `known-defect`).
