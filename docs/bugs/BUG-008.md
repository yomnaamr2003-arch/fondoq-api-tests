# Bug report

- **ID:** BUG-008
- **Title:** POST /booking answers 500 Internal Server Error when a required field is missing
- **Endpoint:** POST /booking
- **Severity / Priority:** High / P1 - a client mistake crashes the request handler; 5xx also triggers alerts and retries on the client side.
- **Environment:** Local run of the upstream Restful-Booker source (github.com/mwinteringham/restful-booker, commit 619d031) at `http://localhost:3001`, Node 22, 2026-11-15. NOT yet re-run on `https://restful-booker.herokuapp.com` (blocked from the sandbox the suite was built in) - re-run the suite on the public environment before sending.

## Steps to reproduce
1. Send `POST /booking` without `firstname` (other fields valid).
2. Repeat with each of `lastname`, `totalprice`, `depositpaid`, `bookingdates` missing in turn.
3. Send `POST /booking` with an empty JSON object `{}`.

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
curl -i -X POST $BASE/booking -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"lastname":"B","totalprice":10,"depositpaid":true,"bookingdates":{"checkin":"2026-11-02","checkout":"2026-11-05"}}'
```

## Expected result (quote the contract)
Contract, Booking object: these fields are **required**; POST -> **400** when a rule is broken. A 4xx is the correct class for a client error, never 5xx.

## Actual result (status, body, timing)
Every one of these requests returns **500 Internal Server Error** with body `Internal Server Error` (2 ms).

```
HTTP/1.1 500 Internal Server Error
Content-Type: text/plain; charset=utf-8

Internal Server Error
```

## Evidence
Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 05, requests 'missing "firstname" key', 'missing "bookingdates"', 'empty JSON object'; REST Assured: `BookingValidationBddTest.missingRequiredFieldIsRejected` (6 scenarios).
