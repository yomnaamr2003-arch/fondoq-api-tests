# Bug report

- **ID:** BUG-006
- **Title:** POST /booking accepts an invalid date and stores it corrupted ("0NaN-aN-aN")
- **Endpoint:** POST /booking (TC14)
- **Severity / Priority:** High / P1 - silent data corruption: the request succeeds but the stored dates are garbage.
- **Environment:** Public server `https://restful-booker.herokuapp.com` (REST Assured run, 2026-11-17: 46 tests, 19 failures = the `known-defect` tests) and a local run of the upstream Restful-Booker source (commit 619d031) at `http://localhost:3001` (Postman/Newman, 2026-11-15). Response examples below are from the local run.

## Steps to reproduce
1. Send `POST /booking` with checkin `2026-13-01` and checkout `2026-13-04` (month 13) (TC14).

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
curl -i -X POST $BASE/booking -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"firstname":"Farida","lastname":"Zaki","totalprice":1300,"depositpaid":true,"bookingdates":{"checkin":"2026-13-01","checkout":"2026-13-04"}}'
```

## Expected result (quote the contract)
Contract, Booking object: `bookingdates.checkin` / `checkout` -> **date YYYY-MM-DD**, required; POST -> **400** when a rule is broken.

## Actual result (status, body, timing)
Status **200**; the response and the stored booking contain `"checkin":"0NaN-aN-aN"`, `"checkout":"0NaN-aN-aN"`.

```
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"bookingid":38,"booking":{"firstname":"Farida","lastname":"Zaki","totalprice":1300,"depositpaid":true,"bookingdates":{"checkin":"0NaN-aN-aN","checkout":"0NaN-aN-aN"}}}
```

## Evidence
Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 07 (CSV), iteration TC14; REST Assured: `BookingValidationBddTest.invalidBookingIsRejected` (TC14).
