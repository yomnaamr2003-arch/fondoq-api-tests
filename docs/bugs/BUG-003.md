# Bug report

- **ID:** BUG-003
- **Title:** POST /booking accepts an empty firstname or lastname
- **Endpoint:** POST /booking (rows TC08, TC09 of booking_test_data.csv)
- **Severity / Priority:** Medium / P2 - bookings without a guest name reach the hotels.
- **Environment:** Local run of the upstream Restful-Booker source (github.com/mwinteringham/restful-booker, commit 619d031) at `http://localhost:3001`, Node 22, 2026-11-15. NOT yet re-run on `https://restful-booker.herokuapp.com` (blocked from the sandbox the suite was built in) - re-run the suite on the public environment before sending.

## Steps to reproduce
1. Send `POST /booking` with `"firstname": ""` and all other fields valid (TC08).
2. Send `POST /booking` with `"lastname": ""` and all other fields valid (TC09).

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
curl -i -X POST $BASE/booking -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"firstname":"","lastname":"Mahmoud","totalprice":900,"depositpaid":true,"bookingdates":{"checkin":"2026-11-20","checkout":"2026-11-22"}}'
```

## Expected result (quote the contract)
Contract, Booking object: `firstname` / `lastname` -> string, **required, not empty**; Endpoints table: `POST /booking` -> **400** when a rule is broken.

## Actual result (status, body, timing)
Both requests return **200** and a new booking with the empty name stored.

```
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"bookingid":32,"booking":{"firstname":"","lastname":"Mahmoud","totalprice":900,"depositpaid":true,"bookingdates":{"checkin":"2026-11-20","checkout":"2026-11-22"}}}
```

## Evidence
Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 07 (CSV), iterations TC08 and TC09; REST Assured: `BookingValidationBddTest.invalidBookingIsRejected` (TC08, TC09).
