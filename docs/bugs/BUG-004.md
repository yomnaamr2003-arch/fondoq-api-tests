# Bug report

- **ID:** BUG-004
- **Title:** POST and PUT accept totalprice 0 and negative prices
- **Endpoint:** POST /booking (TC10, TC11); PUT /booking/{id} (found while exploring)
- **Severity / Priority:** High / P1 - zero or negative prices corrupt revenue figures and could mean refunds.
- **Environment:** Public server `https://restful-booker.herokuapp.com` (REST Assured run, 2026-11-17: 46 tests, 19 failures = the `known-defect` tests) and a local run of the upstream Restful-Booker source (commit 619d031) at `http://localhost:3001` (Postman/Newman, 2026-11-15). Response examples below are from the local run.

## Steps to reproduce
1. Send `POST /booking` with `"totalprice": 0` (TC10).
2. Send `POST /booking` with `"totalprice": -150` (TC11).
3. Create a valid booking, then `PUT /booking/{id}` (valid token) with `"totalprice": 0`.

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
curl -i -X POST $BASE/booking -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"firstname":"Heba","lastname":"Nour","totalprice":-150,"depositpaid":false,"bookingdates":{"checkin":"2026-11-20","checkout":"2026-11-22"}}'
```

## Expected result (quote the contract)
Contract, Booking object: `totalprice` -> integer, required, **greater than 0**; Endpoints table: POST -> 400 when a rule is broken, PUT -> **400** invalid body.

## Actual result (status, body, timing)
POST returns **200** for 0 and for -150 and stores the value. PUT with price 0 also returns **200** (`totalprice` 0 in the response body).

```
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"bookingid":35,"booking":{"firstname":"Heba","lastname":"Nour","totalprice":-150,"depositpaid":false,"bookingdates":{"checkin":"2026-11-20","checkout":"2026-11-22"}}}
```

## Evidence
The PUT variant was checked on the local copy only. Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 07 (CSV), iterations TC10 and TC11; REST Assured: `BookingValidationBddTest.invalidBookingIsRejected` (TC10, TC11). The PUT variant was found manually and is not automated yet.
