# Bug report

- **ID:** BUG-005
- **Title:** POST /booking accepts checkout on or before checkin
- **Endpoint:** POST /booking (TC12, TC13)
- **Severity / Priority:** High / P1 - zero or negative-length stays break availability and pricing.
- **Environment:** Local run of the upstream Restful-Booker source (github.com/mwinteringham/restful-booker, commit 619d031) at `http://localhost:3001`, Node 22, 2026-11-15. NOT yet re-run on `https://restful-booker.herokuapp.com` (blocked from the sandbox the suite was built in) - re-run the suite on the public environment before sending.

## Steps to reproduce
1. Send `POST /booking` with checkin `2026-11-25`, checkout `2026-11-23` (TC12).
2. Send `POST /booking` with checkin and checkout both `2026-11-25` (TC13).

Reproduce with curl:

```bash
BASE=http://localhost:3001   # or https://restful-booker.herokuapp.com
curl -i -X POST $BASE/booking -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"firstname":"Aya","lastname":"Samy","totalprice":1100,"depositpaid":true,"bookingdates":{"checkin":"2026-11-25","checkout":"2026-11-23"}}'
```

## Expected result (quote the contract)
Contract, Booking object: `bookingdates.checkout` -> required, **after checkin**; POST -> **400** when a rule is broken.

## Actual result (status, body, timing)
Both requests return **200** and the booking is stored with the impossible dates.

```
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"bookingid":36,"booking":{"firstname":"Aya","lastname":"Samy","totalprice":1100,"depositpaid":true,"bookingdates":{"checkin":"2026-11-25","checkout":"2026-11-23"}}}
```

## Evidence
Captured output above (response time 1-3 ms, well under the 2 s limit, so only the behaviour is wrong). Automated detection: Postman: `fondoq-booking.postman_collection.json` -> folder 07 (CSV), iterations TC12 and TC13; REST Assured: `BookingValidationBddTest.invalidBookingIsRejected` (TC12, TC13).
